# Cart Plan — Sprint 9

## Objective

Add a session-local shopping cart to the FlowDelivery app, allowing authenticated
users to add products from `ProductDetailsPage`, review items in a dedicated Cart
page, adjust quantities, and see a running total — without any remote persistence
or checkout behavior.

## Architectural Context

Sprint 8 established a complete read-only browsing flow:
Home → Restaurant Details → Product Details. `ProductDetails` already carries
all fields needed by a cart item (`id`, `restaurantId`, `name`, `priceInCents`,
`imageAssetPath`). The `ProductDetailsPage` currently has no user action beyond
navigation back.

Cart is mutable session state. It does not require a Supabase datasource or
repository — the domain boundary is the `CartNotifier`, which owns the cart
aggregate in-memory via Riverpod. This differs from previous read-only features
that used `FutureProvider.family`; Cart uses `Notifier<Cart>` because the state
is write-driven.

```text
ProductDetailsPage
  └── onAddToCart(ProductDetails) callback
        ↓
  CartNotifier (Notifier<Cart>)   ← single source of truth
        ↑               ↑
   CartPage        cart badge
  (/cart route)   (AppBar / nav)
```

No repository or datasource layer is introduced. The `CartNotifier` is the
ViewModel equivalent for this feature. Persistence across app restarts is deferred
to the Checkout sprint, when session continuity has real value.

### Single-Restaurant Constraint

Standard food delivery rule: a cart may only contain items from one restaurant.
Adding a product from a different restaurant triggers a confirmation dialog.
On confirm → clear cart and add the new item. On cancel → no-op.

## Scope

- `CartItem` and `Cart` domain entities (pure Dart, immutable, value equality);
- `CartNotifier` with `addItem`, `removeItem`, `updateQuantity`, `clear`, and
  single-restaurant enforcement;
- `cartProvider` (`NotifierProvider<CartNotifier, Cart>`) registered at app level;
- Route `/cart` (protected, authenticated);
- `CartPage` — states: empty, non-empty (item list, quantity controls, total);
- "Proceed to checkout" CTA on `CartPage` — visible but disabled (placeholder);
- Cart item count badge integrated into the existing AppBar or navigation area;
- "Add to cart" action on `ProductDetailsPage` — shows quantity controls when
  already in cart;
- ARB copy for all cart user-facing strings across pt_BR, pt, and en;
- Localization Guard and Theme Guard compliance;
- Focused tests: `CartNotifier` unit tests + `CartPage` widget tests (empty,
  non-empty, single-restaurant dialog).

## Out of Scope

- Supabase cart persistence, `shared_preferences`, or any cross-session storage;
- Checkout, payment, order creation, and delivery address selection;
- Product customization (variants, add-ons, special instructions, quantity on
  product-details pre-add);
- Coupon/discount codes;
- Delivery fee calculation;
- Favorites, profile, Realtime, and any other feature domain;
- Cart sharing or deep links into cart state.

## Risks

- Single-restaurant dialog UX must be clear enough that demo reviewers understand
  the intentional constraint rather than experiencing it as a bug.
- `CartNotifier` must remain outside presentation to stay testable.
- Price formatting duplication (`_formatPrice`) currently exists in
  `restaurant_details_sections.dart` and `product_details_sections.dart`. Cart
  introduces a third consumer — consider extracting to `lib/shared/` in this
  sprint (Task 1, accepted only if two files already duplicate it).
- Badge counter must not cause a rebuild of the entire page tree; scope the watch
  to a derived `cartItemCountProvider`.

### Task 1 — Domain: CartItem, Cart, and CartNotifier

**Goal:** Define the complete cart domain and state manager without touching any
presentation file.

**Files to create:**
- `lib/features/cart/domain/entities/cart_item.dart`
- `lib/features/cart/domain/entities/cart.dart`
- `lib/features/cart/presentation/providers/cart_providers.dart`

**Contracts:**

```dart
// CartItem — immutable, value equality
class CartItem {
  final String productId;
  final String restaurantId;
  final String restaurantName; // for single-restaurant dialog copy
  final String name;
  final String imageAssetPath;
  final int priceInCents;
  final int quantity;          // >= 1

  int get subtotalInCents => priceInCents * quantity;
}

// Cart — aggregate, immutable
class Cart {
  final List<CartItem> items;  // unmodifiable view

  bool get isEmpty;
  int get itemCount;           // sum of quantities
  int get totalInCents;        // sum of subtotals
  String? get restaurantId;    // null when empty
}

// CartNotifier — Notifier<Cart>
class CartNotifier extends Notifier<Cart> {
  void addItem(ProductDetails product, {String restaurantName});
  void removeItem(String productId);
  void updateQuantity(String productId, int quantity); // quantity 0 → removeItem
  void clear();
}

final cartProvider = NotifierProvider<CartNotifier, Cart>(CartNotifier.new);
final cartItemCountProvider = Provider<int>((ref) => ref.watch(cartProvider).itemCount);
```

**Validation:**
- `dart analyze lib/features/cart`
- Unit tests (Task 7) cover all `CartNotifier` operations.

**Localization Guard:** none (pure domain, no UI strings).
**Theme Guard:** none (no UI).

### Task 5 — Integrate ProductDetailsPage with CartNotifier

**Goal:** Add an "Add to cart" action to `ProductDetailsPage`. When the product is
already in the cart, show quantity controls instead of the add button. Trigger the
single-restaurant confirmation dialog when needed.

**Files to update:**
- `lib/features/product_details/presentation/pages/product_details_page.dart`
- `lib/features/product_details/presentation/widgets/product_details_sections.dart`

**Behavior:**

```
Product NOT in cart → FilledButton "Adicionar ao carrinho"
  └── tap → check cart.restaurantId
        ├── same restaurant (or empty cart) → cartNotifier.addItem(product)
        └── different restaurant → show AlertDialog (Task 2 copy)
              ├── confirm → cartNotifier.clear() + cartNotifier.addItem(product)
              └── cancel  → no-op

Product IS in cart → QuantityControl row  (− [qty] +)
  ├── + → cartNotifier.updateQuantity(productId, qty + 1)
  └── − → cartNotifier.updateQuantity(productId, qty - 1)
        └── qty reaches 0 → cartNotifier.removeItem(productId)
```

**Note:** `ProductDetailsPage` reads `cartProvider` only for the action area —
derive a `cartItemProvider(productId)` selector to avoid rebuilding the hero on
every cart change.

**Validation:**
- `dart analyze lib/features/product_details`
- Widget tests for the "add" and "already in cart" states (Task 7).

**Localization Guard:** `cartAddToCart`, `cartAlreadyInCart`, dialog strings.
**Theme Guard:** action button uses `FilledButton`; quantity controls use semantic
colors.
