# FlowDelivery v0.6.0

Release date: 2026-07-08

## Objective

Publish the Sprint 12 Order History milestone on top of the v0.5.0
payments foundation, closing the first write -> read loop in the app with
a protected read-only `/orders` experience for authenticated users.

## Included

- New `orders` feature module across domain, data, and presentation layers.
- Pure-Dart order history contracts: `OrderHistoryEntry`,
  `OrderHistoryStatus`, and `OrderHistoryRepository`.
- Supabase-backed read path using one embedded PostgREST query over
  `orders`, `restaurants`, and `order_items(quantity)`, ordered by newest
  first and scoped by existing RLS ownership.
- Repository DTO -> domain mapping plus explicit remote/domain failure
  handling for order history reads.
- `orderHistoryProvider` implemented as a `FutureProvider` read slice,
  following the established no-ViewModel precedent for simple read-only
  surfaces.
- Protected `/orders` route and Home bottom navigation wiring for the
  `Pedidos` destination.
- Localized order history UI states for loading, empty, error, and success,
  with grouped sections and order cards.
- Order history copy added across pt_BR, pt, and en with regenerated
  `AppLocalizations` outputs.
- Sprint 12 documentation, memory, technical debt notes, and Trello
  reconciliation completed after validation.

## Architecture

Order history extends the validated commerce path with the first
user-scoped readback of persisted transactional data:

```text
OrdersPage
  -> orderHistoryProvider (FutureProvider)
  -> OrderHistoryRepository
  -> OrderHistoryRemoteDatasource
  -> Supabase PostgREST query (orders + restaurants + order_items)
```

This slice remains intentionally read-only: it introduces no new migration,
no new write behavior, and no status transitions. The database still
constrains the surfaced history to the honest `placed` status.

## Known Limitations

- Order history remains read-only: no reorder, cancellation, editing, or
  order details page yet.
- Status transitions, tracking timeline, Realtime updates, filtering,
  searching, pagination, and history tabs remain future slices.
- Delivery address is still a localized demo placeholder, not
  profile-backed data.
- Payment remains a demo cash-on-delivery flow without gateway
  integration or settlement lifecycle.
- Cart persistence across app restarts remains planned scope.
